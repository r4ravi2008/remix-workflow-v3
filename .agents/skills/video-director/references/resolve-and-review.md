# Resolve assembly and review

Require [quality-gates.md](quality-gates.md) acceptance for consumed components and separate acceptance for scoped edits, the optional wrapper, and the final export. Compare actual timeline media/dependencies with the quality manifest before finishing.

## Establish the live project

Discover available Resolve integrations and current build. Prefer the official native MCP for supported operations, using community tools when they supply a needed capability. Load the relevant installed Resolve skill and tool documentation before calls. Inspect version/support capabilities when available. Probe uncertain methods on a duplicate timeline; historical scripts are examples, not API guarantees.

Before changing a shared Resolve session, inspect the active project/timeline and any live render job. Coordinate with a known current owner if necessary. Save the outgoing project before an authorized switch. Do not stop another task or render merely because an old task title looks related. Use a named project and versioned timeline for this video. Export a recoverable project/timeline checkpoint before substantial edits; never patch a live database.

Compare the live project with the source/audio/workspace binding in [project-record.md](project-record.md). Keep generation, upscale comparisons and editing from colliding on shared GPU/Resolve resources. Inspect live ownership and queue state before heavy work; reserve/release resources through the existing run workflow. Send coordination messages only when the user has authorized messaging that chat. While a resource is occupied, complete independent preparation rather than restarting services or switching another owner's project.

Set timeline dimensions and rational frame rate before assembly. Keep absolute source/audio/speech seconds, zero-based timeline frame offsets, and Resolve timeline start frame/timecode distinct. Convert an event with `round(seconds * fps)` using the actual frame rate, and add the timeline start only where the API expects it. Use half-open edit ranges internally, converting tool-specific inclusive ends at the boundary. Test a short known interval before a full import. If required splitting, retiming, or effects are unavailable through the current API, use documented UI control or supported timeline interchange on a duplicate; verify the result in Resolve rather than inventing methods.

## Assemble to the content map

Import only verified media and record audio owners. For music, lay the canonical song on its own track, mute unintended source/generated clip audio, and add section/selected beat markers from the listened map. For spoken stories, place the reviewed narration, align speech/idea markers and planned evidence graphics, and retain only intentional source sound. A deliberate silent brief needs no fabricated soundtrack. Before accepting each source range, apply [composition-and-finish.md](composition-and-finish.md): confirm the face or landmark is visible, the focal action is in focus, and the chosen crop remains useful through motion. Build scenes and coverage first, then transitions, retimes, grade, and typography. For a bounded revision, record the chosen interval and observed problem, preserve the unaffected ranges, and verify before/after audio identity, range, and track ownership. If accepted coverage cannot meet a no-generation request, preserve the checkpoint and provide a precise blocked edit plan. Keep separate tracks or bins for source clips, generated footage, overlays, and text so revisions remain tractable. Duplicate the accepted timeline before structural changes and keep a recoverable checkpoint.

For music, a tempo grid suggests anchors; it does not decide every edit. Use phrase-level changes, varied shot lengths, selected accent cuts, and movements that crest on musical events. Record intentional off-beat/syncopated edits. Avoid mechanical repeated scale jolts. For a mellow treatment, hold across beats and use movement or light as the response. “Production heavy” can mean strong continuity and careful finishing rather than dense effects.

Implement transitions and composites in Resolve/Fusion using supported controls. Check actual readback and rendered frames after properties change. A successful API call alone does not prove an effect was applied. Preserve handles and inspect for single-frame gaps, black flashes, frozen frames, bad crops, and interpolation artifacts. Audit every time map and transition event for monotonic source order unless a deliberate reverse is recorded. Do not preload the incoming shot's visible motion before the cut and then restart it at source frame zero; that creates apparent backward time. Keep aspect ratio intact. If filling a frame requires cropping, inspect the crop for each shot; never stretch people.

Resolve any explicit stillness policy into measurable review evidence. If the brief forbids static intervals, configure a near-identical-frame detector with the requested duration threshold, inspect every candidate visually, and repair accepted true holds with real motion or a redesigned edit. Do not treat compression noise as motion or universalize one project's threshold. If held shots are allowed, distinguish intentional stillness from frozen media and record which is which.

## Speech, captions and story graphics

For news and spoken stories, bind script, source/claim ledger, narration hash and speech cues before assembly. Cut to complete spoken ideas and purposeful pauses. Give evidence and comparisons enough time to understand; moving text or rapid cuts cannot rescue an overloaded script. Keep captions, headline, source labels and illustrative disclosures independently editable with a single owner per role. Verify the full audible transcript and visible values/qualifiers against the script. A corrected caption cannot fix a wrong voice take. Read [news-bytes.md](news-bytes.md) for factual/Telugu requirements.

Include all rendered text roles in `text_events` (stable occurrence ID, role, half-open start/end frames) for the event review. Inspect entrance, readable hold, exit and mobile composition through the actual motion, including source/disclosure dwell. No lyric pipeline or beat effects are required for speech.

## Lyrics, for music when requested

Run [lyric-art-direction.md](../../music-video-director/references/lyric-art-direction.md) after scene order, vocal timing, transitions and grade are stable enough for previews, before full lyric rollout and final export. Record the selected type/motion families and scene-state mappings, then read [typography-and-story-graphics.md](../../music-video-director/references/typography-and-story-graphics.md) for implementation, message semantics, tracked text and nested text ownership. Keep story graphics independently editable and reviewable from lyrics.

Bind alignment to the exact selected audio hash and version. Preserve the canonical text; maintain separate display/translation/transliteration files with explicit labels. Strip generation tags from visible lyrics. If words or timing change, invalidate only dependent alignments, overlays, and exports.

Validate repeated choruses and the last verse/outro individually. A successful opening alignment does not prove the final minute is correct. Keep a line-to-time map and inspect low-confidence passages with the actual audio. Respect the requested writing system and confirm font coverage.

Compose lyrics in suitable negative space, away from faces and key gestures. Use verified tracking only when the chosen design calls for text anchored to a moving surface. Choose readable duration and motion based on the phrase. Pilot alternate layouts in the rendered picture at actual desktop and phone sizes; legible text in a low black strip can still be visually weak. A lyric contact sheet should cover every line placement, then motion review checks entrances, exits, and moving subjects. Transliteration is not translation; do not silently change meaning or call guessed English text transliteration.

Apply the recorded theme/layout and animation timing per cue; preserve a readable hold and inspect material/font changes across narrative worlds. Temporary SRT-style bottom captions are not completion of an expressive lyric brief. Keep the chosen design editable and verify that no older lyric track remains visible underneath it.

## Optional Remotion presentation

Use an existing or explicitly selected Remotion workflow when appropriate and read its docs. Load `remix-phase-two` and the local video-generator README only for the music/remix layout they implement. Do not force a news short into that template. Use the finished Resolve film as the video source. Choose one audio owner and one lyric owner to prevent doubled sound or duplicate text. Match the card to the film's aspect ratio, check any crop, and derive surrounding colors from the current song treatment.

For music, the Yemi/Udi presentation used a large film area, a bottom visualizer, song information around it, and no internal tooling/version labels. This is a reusable option, not the default for standalone films. Recheck the wrapper's final export after every source-film correction.

For a vertical recut of any category, do not solve composition with one global center crop. Choose and position footage shot by shot so faces, gestures, props, and story information remain inside the mobile frame through the whole shot. Inspect head, middle, and tail frames plus actual motion; then adjust the enabled text roles using rendered font metrics. When the user specifies how prominent the embedded film should be, measure that proportion in the final wrapper rather than inferring it from the template.

When an adaptive layout is appropriate, use full-height framing for a single subject when the whole action fits, and a larger centered wide composition for two-person/action/message shots that require more width. Choose from the actual shot, not an automatic “all portrait” or “all letterbox” rule. Measure requested prominence in the delivered pixels; a fixed widescreen strip can be technically intact but too small to read on mobile. Reposition captions/lyrics/graphics with the framing mode and inspect the mode changes for distracting size jumps. User-specific percentages are project requirements, not global presets.

A duration cap does not authorize cutting essential spoken/music phrases, dropping factual qualifiers or speeding up audio. If the user permits a speed change, keep an immutable canonical original and record a derived picture/audio/text time map, speed and pitch treatment. Apply it consistently to lyrics, messages, accents and the ending; verify actual rendered duration and audible quality. Nested timelines can retain old lyrics and widescreen text canvases after a layout change. Verify inner track state and use the portrait canvas for replacement text. Check still/title carriers' actual end frames after import, because default still durations can override intended cue lengths.

## Export and prove the result

When upscaling is requested or accepted low-resolution footage needs enlargement, run [upscaling-and-restoration.md](../../music-video-director/references/upscaling-and-restoration.md) before the final render. Compare source-level processing at equal output size, preserve the accepted time maps and overlays, and apply only reviewed improvements. Raising the export resolution alone is not an upscale quality pass.

Render to a new versioned destination and retain project/timeline identity, settings, and job ID. Poll that specific job until completion or a real failure. If polling times out, inspect the existing job before submitting another. Verify the file exists and decodes; inspect duration, dimensions, frame rate, audio streams, silence/clipping anomalies, and whether the intended ending survives. Compression can change file hashes; use decoded audio comparison or aligned listening to verify the correct bound song/narration/mix.

Review bounded corrections in rendered motion before propagating the pattern. When the user sets a range gate, stop exactly there; otherwise use the shortest diagnostic that proves the risky behavior, then inspect the assembled full film for cross-boundary regressions. Contact sheets should first verify macro scene order, then the outgoing clean frame, transition span, incoming clean frame, and causal readability.

Review the exact final file at normal speed with sound. Watch the full deliverable when claiming a complete creative review. At minimum, a provisional review must name the ranges actually checked, including opening, representative transitions, busiest section, repeated material, and ending. Before any completion claim, create and check the [per-shot/cue/join finish matrix](composition-and-finish.md) against the actual exported timeline. Sampled checks remain sampled. Verify:

- Category timing reads as intended: musical phrases/accents or spoken ideas/pauses. No sync drift, rushed explanation or monotonous effect pattern.
- Continuity, believable motion, relevant image roles, any requested character/source-generated treatment and adequate coverage.
- Focal-subject framing through the whole shot, especially after horizontal-to-vertical reframing; important faces and actions are not merely sharp but actually visible and compositionally dominant.
- Timing, meaning and legibility of every enabled text role across the whole video; no obstruction of faces or evidence.
- Coherent color across original and generated material; no accidental borders or distortion.
- No unintended dimming layers, colored guide bars, mask remnants, or Fusion controls left visible; black-frame detection alone will not find a translucent dark overlay.
- Correct forward chronology and causal action; no repeated or regressive invitation, departure, approach, or other story state.
- Focal-subject sharpness at delivery resolution, not merely successful decode or a small contact-sheet thumbnail.
- Clean audio ownership, intelligible speech when enabled, complete spoken/musical phrases and a deliberate final decay/frame.

For factual work also compare all spoken/visible claims, image roles, source labels and uncertainties with the current ledger. Keep `MEASURED`, `FRAME-INSPECTED`, `WATCHED`, `HEARD`, factual verification and `PENDING` evidence separate. If the environment cannot play or perceive audio/video, inspect available exported frames and repair visible defects, then apply [the diagnostic/production boundary](production-workflow.md#when-perception-or-a-required-technique-is-unavailable). Disclose pending viewing/listening on a delivered candidate; that label cannot authorize expanding an unproven treatment. Do not label an observed head/structure crop, soft lead or failed transition as merely pending playback. Never upgrade a contact sheet, waveform, or hash into a claim that the film feels right.

Apply [revision-and-self-review.md](revision-and-self-review.md) before presenting. Record timed viewing/listening coverage using [quality-gates.md](quality-gates.md); for a complete export it must cover the whole exact file. Close the corrections ledger and verify full-render pixels against the successful diagnostics.

Deliver the export, editable Resolve project/checkpoint when available, and the concise review record. Verify the delivered path opens the exact selected revision. For a local review page, check its server and media links before sharing and include an accessible direct video or self-contained review bundle; localhost alone is not a durable or mobile-accessible handoff. Verify cloud-backed files are readable media rather than placeholders, and supply the actual iCloud-relative location when the user needs mobile review.

Do not upload or schedule as a side effect. If explicitly requested, hand off to the available upload skill with the final verified file and retain its publication boundary. Preserve separate endpoint states for each platform: prepared, transferred, processing, saved draft, submitted, scheduled and published. Read back the required saved/provider state and bind its receipt to the asset/account; selecting a file or completing transfer does not prove a draft was saved or a release submitted. Apply each platform's current user instruction rather than carrying one platform's draft/submission choice across the others.
